# WellnessLiving JS SDK — Документация проекта

## 📋 Общее описание

**WellnessLiving JS SDK** (`@wellnessliving/wl-sdk-js`) — это JavaScript SDK для взаимодействия с API платформы WellnessLiving. Платформа предназначена для управления фитнес-клубами, студиями йоги, спа-салонами и другими wellness-бизнесами.

SDK предоставляет модели данных (API endpoints) для работы с различными сущностями системы: бронирование, оплата, расписание, клиенты, персонал и многое другое.

## 🔐 Аутентификация (Authentication Flow)

### Способ 1: С паролем приложения (для мобильных приложений)
```
┌─────────────┐          ┌─────────────────────┐
│  Mobile App │ ──────── │  WellnessLiving API  │
│  (React     │  Signed  │                     │
│   Native)   │  Request │                     │
└─────────────┘          └─────────────────────┘

Шаги:
1. Приложение хранит application password
2. Каждый запрос подписывается через HMAC (SHA-256)
3. Header: Authorization: 20150518,{APP_ID},,{signature}
4. CSRF защита НЕ требуется (нет доступа извне)
```

### Способ 2: Без пароля приложения + CSRF (для веб-страниц)
```
┌─────────┐     ┌──────────────┐     ┌─────────────────────┐
│ Browser │ ──► │  Page Server │ ──► │  WellnessLiving API  │
│         │ ◄── │  (PHP)       │ ◄── │                     │
└─────────┘     └──────────────┘     └─────────────────────┘

Шаги:
1. Browser → WL API: Запрос weak notepad (CORS, проверка Origin)
2. Browser → Page Server: Отправка weak notepad + CSRF code
3. Page Server → WL API: Запрос strong notepad (подписан app password)
4. Page Server → Browser: Возврат strong notepad
5. Browser → WL API: Все последующие запросы подписаны strong notepad

Защита:
- CORS: только зарегистрированные домены
- CSRF: проверка кода на Page Server
- Notepad: привязан к конкретной сессии
```

### Типы сессий
- **Cookie-based** (`SESSION='cookie'`) — для классических веб-сайтов
- **Local Storage-based** — session key хранится в localStorage браузера

### Как использовать SDK (для Frontend):
1. Подключить SDK к проекту
2. Настроить `WlSdk_Config_Mixin` (URL API, App ID, сессия)
3. Создать экземпляр модели (например, `new Wl_Book_Process_ProcessModel()`)
4. Установить параметры запроса
5. Вызвать метод запроса (GET/POST/PUT/DELETE)
6. Обработать результат через Promise/Deferred

### Роли Backend разработчика:
1. **Настройка CORS** — зарегистрировать домен в WellnessLiving
2. **Реализация CSRF endpoint** — генерация и проверка CSRF кодов
3. **Реализация Secret endpoint** — обмен weak→strong notepad через PHP SDK
4. **Хранение application password** — безопасно на сервере, НЕ в JS
5. **Рендер страницы** — внедрение конфигурации SDK и CSRF в HTML

## 🔄 Основные бизнес-флоу (End-to-End)

### Flow 1: Регистрация и вход клиента
```
Login/Add → Profile/Form → Login/Agree → Login/LoginModel → Session
```

### Flow 2: Бронирование группового занятия
```
Schedule/ClassList → Classes/ClassView → Book/Process/ProcessModel →
→ Book/Process/Resource → Book/Process/Purchase → Book/Process/Payment → Visit
```

### Flow 3: Запись на приём (Appointment)
```
Appointment/View → Appointment/Wizard → Appointment/Book → Pay/Form → Visit
```

### Flow 4: Покупка абонемента
```
Promotion/PromotionListModel → Catalog/View → Catalog/Cart/CartModel →
→ Catalog/Payment → Pay/Form → Purchase/Receipt
```

### Flow 5: Покупка товара в магазине
```
Shop/Category → Shop/Product → Catalog/Cart/CartModel →
→ Catalog/Cart/DiscountCodeModel → Catalog/Payment → Pay/Form
```

### Flow 6: Виртуальное занятие
```
Virtual/VirtualScheduleModel → Virtual/Meeting → Integration/Zoom → Visit
```

### Flow 7: Программа лояльности
```
Visit → Reward/Action → Reward/Score → Reward/Board → Reward/Prize
```

### Flow 8: Управление бизнесом (staff)
```
Business/BusinessModel → Location/ListModel → Staff/StaffList →
→ Schedule/Config → Classes/ClassList → Report/Dashboard
```

## 🛠️ Технические детали SDK

| Параметр | Значение |
|----------|----------|
| Базовый класс моделей | `WlSdk_ModelAbstract` |
| Promise реализация | `WlSdk_Deferred` / `WlSdk_Promise` |
| Подпись запросов | HMAC SHA-256 / SHA-3 |
| Кэширование | Встроенное (CLEANUP_TIMEOUT = 3600s) |
| Регионы | Поддержка мульти-региональности (Amazon regions) |
| WebSocket | Поддержка real-time обновлений |
| Конфигурация | Mixin-паттерн (`ConfigAbstractMixin`) |
